# GX10 Decision3 Edge：2 GiB 四核心實測

新的 2 GiB 設定已完成真正原生推論及獨立結果審核。這次證明較小的 Decision3 Edge 能在指定四核心與記憶體上限內完成短請求；尚未代表模型答對率、瀏覽器可用性或完整 JevBench 成績。

| 項目 | 實測 |
| --- | --- |
| 模型 | `vllm-sr/d3-edge`，revision `cab71e6ad3461b8086d51ddb572c656babd63b0b` |
| 執行設定 | CPU 16–19、400% 配額、2 GiB、swap 0；BF16 backbone／FP32 readout |
| 請求 | 一次建構、兩次原生 batch4；每次相同四個獨立合成問題、共 505 input tokens |
| 完整單次時間，含證據寫入與計時器清理 | 1.0770 秒、0.9480 秒 |
| 同一 cgroup 計數視窗的平均核心使用量 | 3.664、3.746；包含框架及驗證開銷 |
| 整個推論指令／外層監督時間 | 15.9170／17.2688 秒 |
| 所選 cgroup 記憶體峰值 | 1,386,991,616 bytes，約 1.29 GiB；包含框架、檔案快取與監督開銷 |
| OOM／節流觀測 | 所有保存的記憶體事件為 0，兩次計數視窗的節流增量為 0 |

實際首層事件兩次均為 `[4, 135, 1024]`，CPU BF16。原始模型、manifest 與選定來源在開始與結束時驗證一致；最終指令退出為 0，原始認證清理完成，兩次程序掃描為空，單元與 cgroup 已不存在。20 秒單次與 120 秒整批限制都保留，成功判斷包含最後寫入與清理後的檢查。

這是同一組合成問題的兩次重複，不是八個獨立品質樣本；短測只確認契約、執行及時間限制。沒有計算語意正確率，也沒有宣稱四倍加速、長上下文通過、與 batch1 品質一致，或推廣到 Decision3 Lite。Lite 先前的實測峰值超過此 2 GiB 上限。

同一閒置視窗也完成文字 helper 的執行環境盤點：真正指令 4.2314 秒，外層 6.0193 秒；9 個原生檔案共 312,553,103 bytes 的前後串流雜湊一致，5 個模組、3 個擴充模組及 13 個來源與選定計畫相符。其 cgroup 峰值為 559,804,416 bytes，清理完成。這項盤點未載入文字模型，亦未產生文字或完成 HTTP 請求。
