# Decision3 text-history：真實瀏覽器首案例配對

日期：2026-10-27

以原始 V7 瀏覽器 runner 和 judge，將 [393／65 text-history 候選](decision3-text-history-cpu-fit.md)與未改動 NF4 基線在同一公開首案例各執行一次。兩臂使用相同案例、seed `20261014`、16 步上限及同一 NF4 文字服務；候選服務確認關閉後才執行基線。這個案例先前已用於模型選型，結果是單例診斷，不能視為未見案例的泛化表現。

| 分支 | Policy calls | Text calls | 實際動作 | 原 judge 成功 |
| --- | ---: | ---: | ---: | ---: |
| text-history 候選 | 3 | 1 | 2 | 0／1 |
| NF4 基線 | 16 | 1 | 5 | 0／1 |

候選依序選擇 TYPE_TEXT、CLICK、DONE；前兩個動作均觀察到頁面變化，但點擊導向案例允許範圍外的頁面，評測記錄 `public_navigation_scope` 錯誤，之後亦記錄過早 DONE。基線執行五個動作後仍未滿足目標，最終達到 16 次決策上限。這次沒有重現前一候選連續四次輸入的行為，但兩個分支仍未完成任務；不同執行的行為差異也不能單憑此案例推論整體改善。

獨立 CPU 審計核對原 judge 的驗證結果、兩臂設定、候選三筆 policy 呼叫與實際 HTTP 請求／回應、共同 GPU 鎖紀錄，以及兩個獨立工作單元的關閉。對候選同次前向特徵進行 FP64 重算，核對原生與調整後共 18 個 head、154 個合法機率及兩次 API 正規化；最大機率絕對誤差為 `1.716193526180021e-7`，最大 entropy 信心值誤差為 `9.671884693140953e-8`。本次服務的見證保存了同次特徵，但沒有另存同次 W0 與增量張量；獨立重算使用先前已釘選的 GPU 基礎權重與候選檔案，服務程式則在每次呼叫核對它們的雜湊。
