# Decision3：雙頭候選的 GX10 數值短測

日期：2026-10-27

以 [465／110 筆訓練資料產生的雙頭候選](decision3-link-navigation-cpu-fit.md)，在 GX10 執行三筆已收錄的訓練請求。三筆均包含 `operation` 與 `click_target`；操作的合法選項數為 4，點擊目標數依序為 1、24、24。測試使用五核心、8 GiB 上限、零 swap 與 120 秒期限，獨立父程序持續監控 ComfyUI 佇列和可用記憶體。

模型的原生讀出、同次零增量控制和雙頭候選回應各包含 61 個合法機率位置。另一個受限 CPU 程序固定來源、訓練請求、兩個增量及同次見證，逐筆以 FP64 重算：原生及零增量控制的最大絕對誤差為 `7.482438119099655e-8`，候選為 `2.211837446530751e-8`。GPU 程序正常退出、最終 CUDA 配置為零，工作單元的 cgroup 已消失。獨立稽核紀錄 SHA256 為 `3e5f17d7e9b53d4220b0848d311920066535b59ec63630b88ee6606ab38b5525`。

在成功執行前，第一個計畫因缺少四個實際載入模組的來源釘選而拒絕繼續；第二個計畫發現 DTO 會重排問題的固定欄位，原檢查因此過嚴。第二次程序退出前未能確認 CUDA 配置歸零，其行程與 cgroup 隨後均已消失。修正後僅容許固定欄位的排列差異，仍核對狀態、決策頭和候選選項的內容與順序；也加入異常清理回歸。失敗執行未計入成功數，紀錄仍保留。

這是訓練請求上的數值與接線驗證，沒有使用開發或封存評測資料，也不代表泛化、真實瀏覽器成功或勝過其他模型。候選尚未完成真實 HTTP／瀏覽器比較，兩套 JevBench 尚無此候選的新分數。
