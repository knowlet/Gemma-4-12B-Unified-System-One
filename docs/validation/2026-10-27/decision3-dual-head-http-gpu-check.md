# Decision3：雙頭候選的本機 HTTP／GPU 短測

日期：2026-10-27

以[同一雙頭候選及受監督 GPU 程序](decision3-dual-head-gpu-check.md)，將一筆已收錄的訓練請求經 IPv4 loopback HTTP 送入 GX10。請求包含 4 個操作選項及 24 個點擊目標；候選服務使用同 inode 的合作式 GPU forward 租約，客戶端完整讀回回應後才記錄成功。此租約僅約束採用相同協定的呼叫者。

另一個受限 CPU 程序核對原始請求、共享租約的取得與完成紀錄、客戶端收到的回應、同次 GPU 見證及固定權重。它逐一比對 HTTP 命名答案與原生候選機率及選項順序，並以 FP64 重算每組 28 個合法機率位置：原生及同次零增量控制最大絕對誤差為 `3.764970835096193e-8`，雙頭候選為 `6.730512924768561e-9`。GPU 程序正常退出，最終 CUDA 配置為零，cgroup 已消失。獨立稽核紀錄 SHA256 為 `e6073466c511b28182e9bf4e5912b3023df1b9954909b4c1bc46b49b9ffbe749`。

這是一筆訓練請求的本機 HTTP 與數值接線驗證；它不代表一般 HTTP 工作負載、真實瀏覽器成功率或勝過其他模型。真實瀏覽器對照及兩套 JevBench 分數仍待完成。
