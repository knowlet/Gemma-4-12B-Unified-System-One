# Decision3：雙頭介面與評測追蹤的合成驗證

日期：2026-10-27

為[跨文件連結候選](decision3-link-navigation-cpu-fit.md)準備原生雙頭介面：保留同次前向的原始讀出，僅對實際提供的 `operation` 與 `click_target` 套用各自的 FP32 增量，並記錄同次零增量控制與私有數值見證。另一個 CPU 稽核器以 FP64 重算合法選項的機率、選擇與熵；單一選項必須為精確的機率 1。介面限定文字請求及一至四個 choice heads，並使用互斥鎖保護單一介面的推論與關閉。

評測追蹤器保留原題 ID、選項及順序，分開記錄一般路徑與瀏覽器雙頭的參與情況；它不計算模型分數。原始 bytes 的雜湊與正規化封包雜湊分開記錄，字典輸入沒有可宣稱的原始 wire 雜湊。對一般路徑，即使題目 ID 與瀏覽器頭同名，也不視為雙頭已參與。

合成測試涵蓋原生 DTO 接線、兩頭與缺席頭、單一選項、並行拒絕、錯誤清理、見證寫入與 FP64 重算，以及兩套評測相關的輸入和計數。這些測試使用替身 provider，並非真實 GPU 或瀏覽器測試。單一介面內的鎖不保護其他介面直接使用同一 provider；實際執行仍須由外層保證獨佔，固定來源與模型身分，並將完整成功的呼叫、原始請求和見證綁定後獨立稽核。

撰寫本段時尚未以這個新候選執行真實 GPU、HTTP 或瀏覽器對照，也尚未取得其兩套 JevBench 分數；不能由合成測試或訓練集命中數推論真實任務成功率。

後續[三筆訓練請求的真實 GPU 數值短測](decision3-dual-head-gpu-check.md)及[一筆本機 HTTP／GPU 短測](decision3-dual-head-http-gpu-check.md)已完成。僅限 loopback 的 HTTP 接線要求外部提供 GPU 租約、身分與同次見證，並記錄原始請求和回應雜湊；絕對期限涵蓋請求標頭與主體，但無法自行中止阻塞中的 GPU 前向。localhost 合成測試涵蓋慢速連線、身分改變和交付失敗；socket 寫入返回本身不代表客戶端已收到回應，本次短測另核對了客戶端完整讀回。

為後續多步瀏覽器準備了長駐服務生命週期：合成測試涵蓋連續請求、啟動或 listener 關閉失敗、阻塞以及清理；服務仍須由外部程序監督 GPU、主機資源與整體期限。停止等待逾時不等於已中止 GPU 前向，多步真實模型與瀏覽器尚未驗證。

多請求接線會逐筆綁定原生請求、見證與命名回應，並提供比對外部傳入之客戶端實際 bytes 的方法。這項比對不認證 bytes 的擷取來源；真實瀏覽器執行仍須由外層保存並驗證實際傳輸內容，再獨立重算每筆見證。

另準備可選的私有 HTTPX 傳輸擷取器，不修改固定版 V7 runner；只有外層明確注入 sink 才會保存請求與回應的內容 bytes，不保存標頭或憑證。若觀察到重新導向、非空非 JSON 內容或無法排除憑證，擷取會中止該次診斷；HTTPX 回應內容也可能已解壓，不能稱為原始傳輸封包。這項工具僅完成合成驗證，尚未連接真實瀏覽器流程。

候選子程序的合成驗證另涵蓋父子身分握手、最多 16 次請求、共享租約及停止清理。若 listener、socket 或租約的關閉狀態無法確認，子程序不宣稱清理成功，由外層監督者處理原本的工作單元；尚未用此子程序執行真實模型。
