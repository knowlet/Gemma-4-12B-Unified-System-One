# Decision3 text-history：GX10 CPU 候選訓練

日期：2026-10-27

接續 [120 筆 text-history 特徵擷取](decision3-text-history-gpu-features.md)，在 GX10 上重建原有 273 筆操作及 65 筆點擊目標資料，再將新資料接到操作資料後，形成 393／65 筆的兩個訓練集合。原有資料的特徵、標籤、候選數、順序及共用基礎權重均與先前驗收資料一致。新資料的 120 個原始遮罩均只啟用操作訓練，每筆也都只有一個有效操作；此次未新增點擊目標標籤。

各決策頭使用等權重、FP32 SGD，從零增量開始訓練 10,000 步；學習率 0.003、L2 係數 0.0001、batch size 64、seed 20261023。訓練與獨立重算在不同的 systemd 單元中執行，皆重新建構輸入並限制 CPU 15–19、500% CPU、8 GiB 記憶體、零 swap 與 120 秒。訓練程序正常結束。

下表是**訓練資料上的命中數**，不是瀏覽器任務成功率，也不是 JevBench 分數。操作資料的舊、新分組分別為 273、120 筆。

| 決策頭及資料 | 原始權重 | 訓練後 |
| --- | ---: | ---: |
| 操作，舊 273 筆 | 96／273 | 213／273 |
| 操作，新 120 筆 | 36／120 | 95／120 |
| 點擊目標，原有 65 筆 | 20／65 | 65／65 |

前一個 equal 候選在相同的舊 273 筆操作資料上為 [233／273](../2026-10-26/decision3-scroll-state-two-arm-fit-results.md)，本次降至 213／273。這是訓練集上的退步；尚不能由此推論瀏覽器成功率的變化。

獨立 CPU 程序重新重建資料與權重，並以 FP64 逐列計算原始及訓練後的完整訓練交叉熵加半 L2 正則項，以及命中數。訓練程序記錄的對照損失本身也以 FP64 計算：四組損失的最大絕對差為 `4.440892098500626e-16`，命中數一致；訓練前後資料及權重雜湊也一致。獨立重算沒有重播 10,000 次 SGD 更新，因此不證明整段最佳化軌跡。資料快照 SHA256 為 `564642295f7c21cd19679a08f061a9ead5b72b83db0929ad522a84459859e7ff`；待驗證候選紀錄 SHA256 為 `5aac7a312ff1e7a995c702222a346f017d6fe5a56a1ec452f95a03a4ef36c978`，獨立重算紀錄為 `6b0a7fabf4123339a1c6a6e945ac0231b371f36da56f3339122a94e12e0b65b6`。

候選尚未完成原生 GPU 組合驗證、真實瀏覽器比較或兩套 JevBench；不能宣稱模型已改善或勝過其他模型。前次已測候選與未改動 NF4 基線的第一個瀏覽器案例均為 0／1；該結果不適用於本次新候選。訓練來源與評測資料的排除檢查只涵蓋已核對的清單，不能宣稱所有未揭露評測皆無交疊。
