# 瀏覽器 feedback 證據基礎設施

日期：2026-10-27（Asia/Taipei）。本次變更是供後續受監督配對實驗使用的來源與合成驗證，沒有新增真實任務成績，也沒有證明模型能力改善。

- DONE review 的 singleton 結束判斷現在要求原 runner 紀錄中的請求、回應及模型身分與 review 對應；紀錄或 callback 結束後保留的變更會使其保持未解決。序號跨同一 model adapter 生命週期累計，快照有筆數及序列化後接受位元組上限，但不保證序列化期間的尖峰記憶體上限。這是同一來源的關聯，並非獨立判分或網路送達證明，也無法證明 callback 期間沒有發生過又復原的變更。
- HTTPX 私有擷取器可選擇將附帶請求的目的地標為 policy、text、共用或未知，僅輸出固定分類，不輸出網址。預設維持原事件格式；標籤不證明請求用途、成功送達或完整擷取。先前缺乏歸屬的紀錄不能事後依此補標。
- 新的來源保留型單臂 actor 與導航診斷包裝預設不可啟用。前者記錄成功接收並保存的請求、回應與未知項；捕獲或寫入失敗時完整性未確認。後者只匯總固定類別，資料缺失或超限明確標示不完整。導航事件數不等於不重複請求數，觀測覆蓋率及來源真實性仍未驗證。原 benchmark runner 未變更，既有來源雜湊不需改寫。

配對 actor 尚未接上獨立 selector、完整分母稽核、程序與 GPU 監督、獨立 judge 來源驗證及作業系統結束狀態證據；因此不能作為有效的實際配對評測，也不得用合成測試宣稱盲測成功。兩套 JevBench 最近的分開重跑及其限制見 [Decision3 原生重跑報告](decision3-post-feedback-jevbench-native-rerun.md)，其中未啟用這次瀏覽器路徑。

## 兩套 JevBench 的模型檢查依賴

模型 manifest、provider 規格及 tensor 雜湊的共用檢查已抽出為獨立工具，讓兩個評測 owner 不必為這些檢查載入瀏覽器導覽 pipeline。新工具的固定常數及函式結構以靜態方式與舊實作對照；合成測試亦檢查兩套 owner 必須固定新工具的來源。舊版 features 與歷史 release 沒有改寫，舊計畫不會因此自動成為新版本的有效計畫。

這只移除一條已知的間接依賴。部分來源驗證仍發生在 Python import 之後，檔案檢查也不是原子操作；完整動態依賴、實際執行內容的來源可信度，以及官方題組和 scorer 的後續讀取範圍仍未閉合。因此不能據此宣稱新計畫已可安全執行或獲得新分數。

共用 release 載入器現在直接編譯執行已驗證的檔案位元組，並在載入期間來源或模組身分變更時拒絕；測試涵蓋檔案置換、舊 bytecode、模組替換、失敗清理及 Python annotation 行為。這項驗證只涵蓋所載單一檔案，不證明其傳遞依賴、pin 的真實性或載入完成後檔案持續不變。歷史 release 及 pin 未重新建立，舊計畫仍會在來源不一致時拒絕執行。

## 捕獲紀錄的結構核對

新的 source-only 驗證器可依現有 journal 格式核對連續序號、body SHA、特殊檔案、孤立檔及讀取時身分，並保留例外、HTTP 狀態、請求來源與目的地分類。實際長度會被量測並受到上限約束，但現有 journal 沒有預先宣告長度，因而沒有事前長度可比對。它不輸出 body 或路徑，也不能證明捕獲了所有請求、來源真實、送達或任務成功。配對 actor 和 release 載入器的特殊檔案讀取亦以非阻塞方式拒絕 FIFO；合成子程序測試設有逾時。
