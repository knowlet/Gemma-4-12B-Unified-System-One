# Decision3 text-history：本機 HTTP 協定診斷

日期：2026-10-27

在 GX10 上以受限的一次性本機 HTTP 服務，將一筆訓練請求送入[新雙頭 adapter](decision3-text-history-native-gpu-adapter.md)，再使用瀏覽器所需的命名答案格式回傳。實際 HTTP 回應的請求雜湊、答案順序、機率和選項均與同一次原生 GPU 前向的見證及正規化結果相符；服務和程序已結束，CUDA 張量配置回到零。

同一次執行另包含一筆雙零控制及三筆直接候選呼叫。獨立 CPU 程序以 FP64 重算全部五次前向的原生及調整後回應，核對 358 個合法機率、40 個選項及 40 個 entropy 信心值；最大機率絕對誤差為 `2.1521308518623883e-7`，最大信心值絕對誤差為 `1.062754356739859e-7`。原始執行紀錄 SHA256 為 `6dee4e55a8042a1e469a3f16c1468db2613e19b98fe87b32bcf9bb3e87517e2a`，獨立重算紀錄為 `323b877cda0bd38ced5b70ef3f2d12354f50a1f640cb7a30a85b28f5b0c45991`。

這是單次正常請求的協定診斷，並非完整 HTTP 服務測試；未執行真實瀏覽器任務，也沒有新的 JevBench 分數。後續配對測試仍須啟動共用 NF4 文字服務、確保 GPU 前向不重疊，並在同一案例上以原有 judge 比較候選與基線。
