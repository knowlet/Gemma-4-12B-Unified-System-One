# Operation-only readout after the complete DSL01 development comparison

Decision recorded on 2026-10-24 after commit `85a24f9020aa4e2226a9c4789e05d143ba79580e`.

The shared readout improved the complete training objective but reduced valid-target hits on the complete development set from 18/33 to 17/33. Operation hits stayed at 10/24; one select-target hit was lost. The genuine browser diagnostic also failed. The shared candidate remains diagnostic-only. These observations motivate an operation-only experiment; they do not establish that this experiment will improve browser completion.

This is a narrow extension of the existing researched implementation. The reference inventory and licensing are retained in `docs/research/jev-decision3-local-successor-inventory.md`, the DSL01 README and its `UPSTREAM-LICENSE`, and the cached-head/core and native-runtime source records. The pinned Decision3 Edge revision is `cab71e6ad3461b8086d51ddb572c656babd63b0b`. The original Browser Use request construction remains unchanged (model.py SHA `a85ada8458d23642c5c8a4095acf0565e6268f81dcda26f6308942b653e9c9f3`, questions.py SHA `66a7054b85040b949e1757311257ea0c5a843c635f9a40c99f6d15ad660fb422`). No new dependency or upstream API is introduced, and no new external search is claimed for this extension.

The optimizer continues to validate all 132 supervised training rows, then excludes the 36 supervised target rows and the 252 unused rows from fitting. It must not assume operation is the first offered head. No new backbone collection is needed. New candidate/fit capabilities and source hashes must be distinct from the rejected shared candidate. The old source, capabilities and failed results remain immutable.

The new strategy was chosen after development exposure: `dev_used_for_model_selection=true`. Development, sealed, official-gold and exposed browser-diagnostic inputs are forbidden in the optimizer. This is a file-flow restriction, not an OS sealing claim. The sealed set remains unrevealed, and a future protocol/candidate must be fixed before opening it.

Source fakes must distinguish actual reordered/absent operation heads, singleton and partial batches, unchanged target logits, mutation and required-evidence failure. Genuine fitting must independently complete within the unchanged original owner09 CPU5/4GiB/120-second transaction. Numeric inference, browser completion and the two separate JevBench suites require new evidence; none is inherited from the old shared candidate. The fixed four-head/eight-operation DSL training distribution remains a known limitation relative to real browser inputs with fewer offered choices.

## GPU deployment of the combined 109-row candidate

Decision recorded on 2026-10-25 at `805820bd2363d2c6b75ec39beb6d67230c679239`, before implementing this deployment. This reuses the source and licensing research above and [the native GPU research](jev-decision3-gx10-gpu-native-qualification.md); no new upstream revision, dependency or external search is selected. The genuine native GPU diagnostic now has independent short/long numerical evidence. The combined 109-row fit has artifact-integrity evidence only. Neither result establishes adapted inference or browser quality.

The new wrapper needs a distinct 109-row numerical capability binding the fit, delta, unchanged W0, GPU prerequisite, source pins and resource profile. Data acceptance and the former 96-row capability provide no deployment authority. Keep the frozen delta separate from W0, verify the exact CPU-to-GPU FP32 bytes, and retain original baseline evidence separately from the composed response. Source, tensor, fence, evidence and cleanup checks all belong inside the same 20-second call budget.

Keep the original transport-wire hash separate from the provider-payload hash. The existing normal DTO serializer writes question schema fields as `type/instructions/criteria`, whereas these admitted wires contain `type/criteria/instructions`. Publisher `normalize_question` also constructs the former schema order explicitly. This does not reorder heads, criteria, state or instruction content. The numerical caller must normally validate the complete original wire, preserve its transport model, and compare every semantic value and inner mapping order; it must not call those two different serializations byte-identical.

Qualification must include zero-delta equivalence, a nonzero delta, operation in different actual rows, K4/K7/K8, singleton and full-width target boundaries, absence of an operation head, and failures during evidence and cleanup. Genuine numerical qualification uses complete authenticated train-only wires without teacher labels. It is not a held-out accuracy result. A later full browser service needs its own longer-lived owner and complete matched ten-case V7 comparison; both JevBench suites still require separate fresh scores.

## Shared GPU forward lease for the matched browser comparison

Decision recorded on 2026-10-25 after `4d22c8444422c3889612111879903bd8c21bf866`. Reuse the existing project-MIT matched campaign's inode-bound `flock` and durable journal design. The CPU serializer's completion callback cannot establish CUDA completion. The new experimental [GPU serializer](../../scripts/jev_gpu_forward_lease.py) instead requires the explicitly selected registered Torch/CUDA modules and calls their selected `torch.cuda.synchronize(0)` before the completed journal record, final deadline check and unlock. Its caller must authenticate framework origins; Python module names alone are insufficient.

Wrap the entire operation-only composition provider, including mandatory witnesses and terminal callbacks. Keep the HTTP-entry deadline wrapper outside the lease so the same 20-second cooperative budget includes waiting for the other model. For the NF4 helper, retain hooks around the complete CausalLM, including its output head and softcap. Both processes must share the exact lock/journal inodes and a distinct campaign lease nonce. Failures before unlock retain the acquired lease until the owned process exits; failure after kernel unlock must report that the lease was released.

The [invented controls](../../tests/test_jev_gpu_forward_lease.py) cover ordering, original error preservation, inode replacement, contention, deadline failure, failed fences/journal writes and the post-unlock close edge. These are stdlib fixtures with named module doubles, not actual Torch or GPU measurements. A separate model-free hardware control verifies the longer owner's configured resource limits and original scoped closure. Neither establishes a live GPU service or browser completion. Preserve the exact ten-case order, same resident NF4 helper, and one separately owned Decision3 service per candidate case when assembling the full comparison.
