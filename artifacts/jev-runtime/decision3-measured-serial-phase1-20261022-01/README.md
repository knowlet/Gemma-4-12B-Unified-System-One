# Full D3 measured serial phase1 component

This is a source-only component for a future owned constructor and original
publisher text48 measurement. It has no executable model actor, HTTP listener,
browser, READY signal, quality score, or launch plan. It is not the original
CORE/helper85 qualification. All six checkpoint identities remain authenticated;
this first measurement explicitly selects full `d3`.

`phase1.run_selected` authenticates an externally SHA-selected component
descriptor and the original selected current-source bootstrap, runtime,
checkpoint cache and publisher source. It builds a separately named backend
whose constructor replaces only original `require_memory` with the measured
gate; the publisher loader kwargs and runtime numerical checks have exact AST
parity. Original inference, normalization, telemetry and close methods are
inherited. Geometry and the genuine publisher 48-call warmup are reused without
reducing the schedule. No adapter/wire/browser is constructed after warmup.

`serial_environment` verifies the selected Transformers loading source and
sets `HF_DEACTIVATE_ASYNC_LOAD=1` before any torch/transformers import, restoring
its previous value after cleanup. The original offline environment and fresh
publisher module-cache requirements still apply. Disabling parallel loading
alone does not select this serial profile. No loader or model is monkeypatched.

The resource profile has separate 6 GiB CPU memcg/swap0, 58 GiB native CUDA
allocator, and 2 GiB prospective nonallocator buffer budgets. Initial host
admission is `R + 6 GiB + 58 GiB + 2 GiB`, where
`R=max(24 GiB,ceil(actual MemTotal/5))`. For selected MemTotal 130595864576 bytes,
this is 96986133300 bytes. Steady host admission is `R+2 GiB`. Actual Driver,
Torch, host, boot and UUID identities must agree before the allocator fraction
is computed from the fresh actual denominator and read back. The cap is set
once; drift, OOM/swap activity, missing ancestry, changed limits/inodes or a
failed observation refuses the attempt. Host reserve is never replaced by
6 GiB memcg headroom. Ancestor event changes are recorded; only selected-unit
pressure/OOM/swap activity is claimed as an automatic event refusal.

Repeated pre-framework/cache gates and both memory checks surrounding helper
authentication retain the original successful identity/event baseline and the
full initial floor. A CUDA-bound baseline cannot return to an initial phase.

`MeasuredHelperChecker` uses an externally selected **fresh** Q95 owner seed,
the exact original95 sources/runtime348, process/listener/private-credential
checks and original no-inference authentication. Its descriptor has fields
`schema_id`, `helper_seed_ref`, `measured_co_resident`, `observations_ref`.
The co-resident fields are `profile`, a fresh `jev-d3-measured-*.service` unit,
and the pure policy's exact `expected` dictionary. Its explicitly different
memory profile retains Q95 initial `R+2BASE`, then the actual Q95 owner's
existing steady `R+2 GiB` rule. It does not claim helper85's original repeated
full-host-floor co-resident qualification. Initial measured D3 admission is
stricter than the initial Q95 floor; neither gets a resident or swap credit.
There is no browser text-connection API in this phase1 checker.

The model process remains offline. Its helper callback must use the existing
nonce/PID/start/request-hash/sequence authenticated control-frame RPC to the
selected checker in the parent. An arbitrary admitted boolean, health check,
old helper seed or direct network callback is not an owner integration.

`owner_sampler.run_owned_sampler` is for an external controller, outside the
model unit, after the original7a50 boundary has verified its selected nonce,
Invocation, actor, cgroup and 6 GiB/swap0 caps. It targets 50 ms host/cgroup
samples and records actual minimum availability, maximum current/kernel peak,
ancestry/event counters and maximum observed gap. A refusal or persistence
failure invokes only that boundary's authenticated close. Successful sampler
return does not authorize continuation; final source checks, whole selected
unit/cgroup and cohort closure remain the external controller's responsibility.
The sampler and Comfy idle/busy observer still need concrete owner integration.

The component descriptor deliberately contains only the six new executable
source files. `source-union.json` records the additional fixed source/runtime
authorities and the checkpoint manifest; it distinguishes saved manifest
declarations from actual payload hashes. This source-only work did not load
models, open Driver libraries, contact a helper/Comfy endpoint, start a unit,
or read tensor payloads. No fresh live helper or launch metadata is fabricated.

Before an actual measurement, a new independently sealed controller must bind
the exact component descriptor, fresh helper/checker descriptor, selected
interpreter/runtime, raw Driver metadata, boot/UUID/MemTotal and fresh unit,
nonces and outputs; run the external sampler and Comfy guard; and own final
cleanup. No such measurement is authorized by this library's dry CLI.

An actual 6 GiB memcg failure may result from GPU/file-cache/temporary charging;
it is a measured resource-profile failure, not a hardware-impossibility claim
or permission to raise limits midattempt. Original text48 reaches 1024 tokens,
so successful phase1 would not qualify an 8192-token activation peak. Its score
stays null until a separately reviewed later complete benchmark campaign.
