# Next measured route to GX10 browser scoring

The immediate candidate for a real small-model comparison is **Decision3 Edge**, not a larger Gemma CPU parity campaign. Its complete runtime file set is already local. The present GPU route is still blocked by admission: approximately 29 GB host MemAvailable leaves only approximately 2.9 GB above the unchanged reserve, while the saved GB10 context probe had only about 0.95 GB CUDA free. Neither a 12.67 GB Q8 GPU load nor the existing Edge GPU replay qualifies under those facts. This note ran no model, compiler, GPU query, tensor/header read, service or download; these are source conclusions and saved observations, not fresh admission.

The original reserve for this 130,595,864,576-byte host is `R=max(24 GiB,ceil(MemTotal/5))=26,119,172,916` bytes. The original small-worker startup floor is `R+2 GiB=28,266,656,564`; native NF4/Q95 helper retains `R+2*23,919,549,408=73,958,271,732`. GPU free and host MemAvailable are never added. Only the original idle observer and fresh actual host/owned-unit observations can authorize a launch. The live download or a reclaimed file cache is not a fabricated resident-memory credit, and nothing here permits Comfy changes.

**1. Finish the current Q8 CPU smoke as a bounded loading/cache proof, then stop treating it as usability evidence.** Fresh v3 explicitly avoids CPU extra-buffer repacking, requests mmap and disables CPU context offload. It can establish actual file backing, full-versus-compact cache behavior, two-position logits and owned memory. A one-CPU/2-GiB 12B smoke, including equality at context 2048, does not establish actual context 8192, browser 20-second latency, TYPE_TEXT or any score. Preserve the original deadline failures and measure real timings; do not replace the deadline or shrink the matched task inventory to obtain a pass.

The existing project `Decision3Backend` explicitly requires CUDA BF16; its replay adds the 2-GiB framework buffer and CUDA floor above. Therefore **neither existing Edge nor Lite replay can honestly run at the stated memory levels**. The smaller core host formula alone is not permission to bypass the selected replay/controller. Lite also exceeds approximately 29 GB even before that replay buffer. A 2-GiB memcg is a further restriction, not interchangeable with host reserve.

The publisher runtime itself explicitly supports `device='cpu'`, BF16 backbone and the original small FP32 255-row readout. Edge's readout file is only 1,044,560 bytes; using that path avoids the native GGUF converter's 1,017,118,720-byte dense FP32 head expansion. This is the most economical **new measurement candidate**: a separately reviewed CPU Edge profile, batch size one, authenticated local sources/weights, and an environment whose DeltaNet bindings are CPU-compatible. The publisher refuses CPU if Transformers bound GPU-only FLA/causal-conv1d kernels; do not fake capability results or mutate a shared environment to evade that guard. Existing project CUDA-only checks must remain intact. Its actual framework/activation peak, fit within the proposed own unit, full verification cost and 20-second latency are unmeasured; no such actor is prepared or admitted by this note.

If that fresh Edge CPU profile passes genuine admission and a real request, reuse the same pinned weights/readout/temperature/prompt contract for Benchmark Heaven public231 and JevBench coherence, reporting their scores separately. Then use the same checkpoint as the policy in the unchanged V7 task/seed/judge/browser wires, preserving 16 steps, the whole 20-second budget, all head/candidate ordering, and actual identity/probability logs. The existing native Decision3 wire preserves up to 255 options and independent questions. CPU batch-one evidence must be reported as its own profile, not the prior GPU batch-eight result.

**3. Prepare the GPU build in parallel only as source/build work; obtain a separate native CUDA admission before loading weights.** NVIDIA identifies GB10 as compute capability 12.1. The local small version file reports CUDA SDK 13.0.3 / NVCC 13.0.88; the pinned CUDA CMake source supports `121a-real` with toolkit 12.9 or newer. A fresh build with one explicit target avoids the upstream default's broad architecture set and native-device discovery; start with one compilation worker under the unchanged owned budget. Actual compiler peak, duration, linked-library identity and GB10 kernels still need measurement. The current CPU library receipt cannot qualify a CUDA library or executable.

The native CUDA source rules out a presumed zero-copy shortcut: `ggml-cuda.cu` advertises `buffer_from_host_ptr=false`, and integrated GPU `mmap_support=false`. The saved probe confirms `is_integrated=1`. AUTO model loading consequently disables mmap for that selected device; GPU tensors get real buffers and `ggml_backend_tensor_set` copies from the file mapping. The opt-in unified-memory setting calls `cudaMallocManaged`, rather than aliasing the GGUF file. Its UMA memory query can report host MemAvailable in place of CUDA free; this is a backend estimate, not the project's reserve/admission rule. Host registration is separately opt-in and is not a demonstrated file-backed CUDA weight path. Neither setting creates extra physical RAM.

The saved tiny context result (`gpu-context-probe-owner-20261023-02/actual-01/fixture/receipt.json`, SHA `a0d3633c69d435fe888e56517ffa98741178eab09221343aa086d5c1fc4107a0`) passed without a model. After init/sync, saved CUDA free was 955,371,520 bytes while host MemAvailable was 28,925,390,848. This is historical, not current CUDA capacity; Torch allocator counters omit context/driver allocations, and a native ggml backend has a different cost. Full Q8 GPU allocation needs more than 12.67 GB plus cache/workspace, so it cannot fit the roughly 2.9-GB reserve margin. A bounded partial-offload study could be considered only after native context/buffer costs and selected per-layer sizes have an independently admitted budget; it is not an already runnable browser configuration. Do not turn on managed memory or rely on automatic layer fitting to manufacture that admission.

**4. Resolve the two product gaps before claiming a complete browser comparison.** The released base Q8 model contains none of the selected native-v2 rank-eight Q/V LoRA (`34a3e20e...`, stat size 20,800,952 bytes). Native adapter conversion/application and GPU numeric behavior need separate proof; reusing the old NF4 or Q95 identity would be incorrect. Ordinary Gemma S1 has a 52-option limit; the existing opt-in hierarchy can retain up to 400 targets but changes the policy and adds measured conditional calls. If needed, declare that separate policy and charge every call to 20 seconds instead of pruning visible targets. Edge's 255-label path is simpler for the direct matched policy, but is still a different model/profile.

Neither S1 slot scoring nor Decision3 produces arbitrary `TYPE_TEXT`. The current syntax helper requires the guarded Torch/PEFT model and cannot simply wrap native Q8/Edge. The browser's existing `text_helper`/endpoint hook is the concrete integration seam for a newly selected real generator, with actual model identity, bounded generation and its own resource accounting. The old pinned helper's 73.96-GB floor is currently unavailable; adding the 12B Q8 helper as a GPU model is also not admitted. No usable low-memory text helper was established in this research. Thus Edge is the smallest next **policy/evaluation** candidate, but a full fixed-ten browser score still requires that real helper; fixture text, replayed fields, deleting TYPE_TEXT tasks or relaxing 20 seconds are not substitutes.

The practical distinction at approximately 29 GB is: small source/build preparation and the already selected bounded CPU smoke may proceed only under their fresh existing admission; a new small Edge CPU measurement is worth preparing but is not yet executable through the current CUDA-only backend; existing Edge/Lite GPU replay, full Q8 GPU browser and the historical N3/Q95 helper are blocked. This identifies required work rather than claiming capability from a refusal or a CPU research pass.
