# Explicit source-only find-text integration

The separate source component and owned CPU Chromium proof establish parser/navigation capability, not a qualified model runtime. The remaining concrete seams are: `s1.api.create_app` imports the original native/generated adapters; the current Decision3 bootstrap selects the original adapter; and the original named-answer wire refuses the experimental native profile ID. None may silently accept FIND_TEXT under an existing baseline label.

This source integration therefore requires an externally selected descriptor SHA and the explicit `jev-find-text-experimental-v1` profile. It reuses the reviewed current bootstrap's checked-source `ProjectSources` importer without calling its model dependencies/constructors. Every selected project source executes fresh checked bytes; existing project modules must be absent, and original module globals/files are never monkeypatched. The three private parser/grammar/native derivatives and the two-identifier wire derivative retain their prior exact inverse proofs.

A private API derivative changes only the two adapter import seams. Original auth, request evidence, profile exclusivity, native twenty-second budget, all submitted question/criterion order, singleton forwarding, native255 limit, probability normalization and argmax remain the original implementation. A bundle factory exposes the private API, explicit named-response conversion and separate Agent subclass. It constructs no backend, model, owner or live service, and does not bind any historical/dead helper seed.

CPU tests will send real valid DTOs through the selected private server and native adapter using a declared simulated numerical backend, then through the exact wire conversion to the unchanged actual Agent in an owned GPU-disabled Chromium fixture. Source/schema/identity mismatch, original-profile rejection, authentication refusal and missing/reordered/wide/invalid-argmax output remain blocking. No production task or judge input is used.

The new descriptor selects source authority only. Actual runtime/cache/model construction, CUDA/kernel/readout geometry evidence, text48 qualification, helper co-residency, HTTP publication/owner lifecycle and full matched benchmark evaluation remain future separately selected work. Existing numerical/floor code is neither copied nor relaxed. Installed-library provenance follows the project's accepted ordinary runtime-version/origin scope; this is not a universal executed-byte security boundary.
