## One smoke request and its limits

Only the future worker creates a fresh random opaque reference string. It submits one original-shape context through the actual frozen public factory and requires native generation to return that string as exact JSON. The string is an input and an assertion, never an alternate generator or a decoded/gold-derived shortcut. There is no task-name matching, benchmark task, gold, DOM fixture, replay or fallback field value in this package. Failed JSON, missing native EOS, timeout, wrong value or evidence failure cannot qualify the smoke.

The transport is **in-process ASGI**, with a declared loopback scope, bearer authentication and native request/response body handling. It is not an actual HTTP connection or listening endpoint. Real loopback serving and policy/browser integration remain later work. One smoke success would qualify one actual NN/ASGI request only; it would not qualify general helper quality, arbitrary browser completion, browser scores, full native DSO closure or hard20. The same fixed helper must be shared across all compared policies, preserving the existing tasks/judge, each task's16-decision budget, each complete request's20-second limit and original options.
