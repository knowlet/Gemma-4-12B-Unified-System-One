# Held train-only loader and bounded readout fit

These sources have not been executed, imported, parsed with AST, formatted or
tested. Both entry points remain `SOURCE_ONLY=True`. The fit capability and
released loader SHA constants are `None`; `loader.pending.json` is an outline,
not a runnable plan. No COMMITTED acceptance or command spec is created here.

The only corpus inputs are the existing DSL01 `corpus/data/train/requests.jsonl`,
`labels.jsonl` and `summary.json`: 96 states, twelve ancestors and four fixed
train families. The optimizer never imports the DSL, generator, audit or full
corpus manifest, and never selects dev, sealed, official or diagnostic arrays.
The loader rejects other paths below the DSL directory. This is an application
input contract; it does not claim OS access sealing.

## Independent acceptance authority

A later root review must select the three exact train export bytes and all
source/model/projection/runtime/W0 identities independently, then examine each
of the twelve original collector invocations. Each needs original root exit0,
owner09 completion without primary/secondary errors, current nonce/admission,
authenticated scoped closure, the original two empty cohort scans and complete
call20/whole120 evidence. Neither a collector Boolean nor its pending filename
authorizes training.

The immutable producer remains `chunk.json` with
`schema=decision3-dsl01-train-feature-chunk-v1`,
`status=PENDING_TRAIN_ONLY`, `training_eligible=false`. Root creates a separate
sidecar with `schema=root-closed-dsl01-train-chunk-acceptance-v1`,
`status=COMMITTED`, `training_eligible=true`, `split=train` and exact DSL/family/
ancestor identity. That sidecar must contain:

- `producer_chunk` and all three `train_inputs` as absolute path/SHA256/size
  refs; the collector itself reads requests/summary only.
- Exact independent `source_records`, `collector_source`, full `model`,
  `projection`, `root_np5_prerequisite_ref` and selected NPY `baseline_sha256`.
- `proof_refs` with root_execution, owner_receipt, closure, admission and
  sealed_config. The loader reads and joins these original proofs.
- `accepted_files` in producer order: baseline, then each case's features, raw
  and evidence refs. Normalize relative paths to the selected chunk directory;
  retain array format/dtype/shape and the W0 `FP32_bytes_sha256` field.
- `transaction` with integer case_count8/call_budget_seconds20/
  whole_budget_seconds120, eight finite complete_call_seconds in (0,20], and
  whole_seconds no greater than120. These values come from the authenticated
  original completed transaction, not a later file-existence check.

Root then creates a separate capability with
`schema=root-selected-dsl01-committed-train-readout-v1`,
`status=ROOT_SELECTED_COMMITTED_TRAIN_ONLY`, the same independent identities,
`baseline` ref, twelve `chunks` entries (ancestor_id, family_id, original chunk
ref, independently accepted sidecar ref), and exactly the declared numerical
policy. `root_np5_prerequisite_ref` pins a genuine
`root-accepted-np5-qualification-v1` whose `numpy_runtime_catalog` ref selects the
already closed nontraining runtime catalog. It does not select that earlier
qualification's diagnostic feature arrays.
An existing repository-relative catalog ref inside this immutable prerequisite
is resolved against the fixed repository root and reauthenticated without
rewriting the original prerequisite.

After source review, the future fit source hardcodes that capability SHA and
the released loader SHA. The capability must not contain hashes of the fit or
loader source: the unchanged original owner09 command spec independently pins
those sources, the capability and frozen core. This avoids circular pins. A
CLI-supplied hash, copied COMMITTED marker or collector-created capability has
no release path. All real pins remain pending in this candidate.

## Data and mathematical joins

Each original chunk contains eight cases in that ancestor's exact train request
order, baseline FP32[255,1024] and per-case FP32[4,1024]. Every payload is rehashed
and loaded with pickle disabled. W0 additionally matches its raw C-order FP32
bytes hash, distinct from the NPY file hash. Finite values, exact dtype/shape and
C order are mandatory.

Rows join case_id + native_payload_sha256 + actual ordered head_id and criterion
IDs. The loader recomputes original DSL request/native hashes, compares the
same-call evidence's original state/questions, validates the four event/row
identities and replays every selected h/W0 through the frozen zero-delta core
against the direct raw native response. It requires legal probabilities within
1e-6+1e-5 relative tolerance, identical ordered argmax, singleton-safe entropy
confidence and exact zero illegal mass. Pending Torch/NumPy diagnostic flags
alone cannot qualify arrays.

Only heads present in the authored label row enter loss. Unused heads are
skipped; they receive no fabricated target. Criteria order, nonempty valid IDs,
positions and uniform authored soft targets must match. Padded columns have
zero target mass; every supervised row sums to one.

## Future bounded fit

The held thin caller uses one original owner09 command on CPU15–19, quota500%,
4GiB and no swap, and joins its actual child identity to the original wrapper,
admission, intent and bounded child-start receipt. It does not construct a new
guardian or imply new no-escape qualification. It verifies selected Python,
NumPy version/build, critical file bytes/stats and mapped math candidate origins
before/after fitting. It reports that limited runtime projection without a full
DSO closure claim; historical Torch candidates need not be mapped by a
NumPy-only optimizer. It never imports a model.

The fixed core `fit_arrays` receives only the authenticated selected arrays:
32 steps, learning_rate0.001, l2=0.0001, seed20261023, batch_size64. A whole120
deadline covers admission, authentication, optimization, final writes and
cleanup through bounded-step cooperative checks; the original owner remains
the outer supervisor. No new hard-preemption guarantee is claimed. There is
no tuning loop or dev/sealed feedback.

Only `delta-pending.npy` FP32[255,1024] and aggregate
`fit-summary-pending.json` are saved in fresh original-owner `fit-head` output.
They remain `PENDING_TRAINED_READOUT_ROOT_ACCEPTANCE`; current original terminal,
owner and closure acceptance is still required. This is no browser, benchmark,
ranking or model quality result, and no normal adapter/manifest is published.

`test_train_loader.py` contains only source-authored fake metadata negatives:
foreign family/request hash, reordered/all-zero labels, changed root acceptance
identity, timing overflow and holds before argument/IO/numerical access. It has
not been run. No real corpus, payload, actual record or weights were read while
authoring these files.
