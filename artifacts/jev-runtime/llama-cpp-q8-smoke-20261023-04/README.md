# CPU4 Q8 arithmetic smoke successor

This source-only successor preserves frozen smoke03. `prepare_smoke.py` and `smoke_common.py` are byte-identical to that predecessor, including original S1 preparation, native payload conversion, synthetic inputs, late-slot search, thresholds, response contract and one-thread Torch preprocessing. The existing selected native v3 source already wires `--threads` to both inference and batch threads; no C++ change or recompilation is needed.

`run_smoke.py` requests `--threads4` in each sequential full2048/compact2048/compact8192 arm. Batch/microbatch512, GPU layers0, CPU mmap mode1, same exact warm/long payloads, contexts, max absolute raw-logit difference0.001 and identical argmax are unchanged. The warm deadline and20-second observation still start immediately before Popen and end only after valid response acceptance within60 seconds. Long calls retain600 seconds from submission through validation. Local evidence finalization is separate. No deadline or mathematical threshold is relaxed.

Bounded native observations retain at most64 `/proc/PID/task` records, each with TID/start identity, user/system CPU ticks, sched masks before/after and proc allowed list. Disappeared or changed tasks remain visible as observation errors; truncated enumeration is explicit. The snapshots quantify observed task population and CPU ticks, not simultaneous busy workers or an all-thread lifetime guarantee. Selected model VMAs retain the existing bounded virtual-mapping scope.

Before native launch, after warm/long completion and on a failed live arm, the scoring actor reads only its exact inherited CPU4 service cgroup `cpu.stat`. Snapshots include usage, user/system, period/throttle counters and monotonic timestamps. Counter deltas report aggregate CPU time divided by wall time and include wrapper/scoring overhead. These are sampled measurements; a four-core mask alone does not prove four busy threads. A failed child is observed only through bounded metadata and is left to the outer original authenticated unit close. No manual kill/terminate or foreign process action is added.

Root supplies a fresh selection with these source refs plus real existing v3 executable/library and public package receipts/stats, and a generic owner03 command spec, before execution. No production selection or actual output is fabricated here. The pure stdlib tests invoke no native binary, Torch, processor, model payload, unit, observer, HTTP or GPU. There is no model accuracy, browser20-second, N3, Q95 or JevBench score claim.
