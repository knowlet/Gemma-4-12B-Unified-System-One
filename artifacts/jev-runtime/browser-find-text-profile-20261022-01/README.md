# Experimental find-on-page component

`jev-find-text-experimental-v1` is a separate, source-only navigation profile. No real browser/model run or score improvement is claimed. The existing eight-operation V7 baselines, tasks, judges, owners and bootstrap descriptor are unchanged.

`make_agent_class(agent_module, model_module, marker_expression=browser_module.MARKER)` returns a new Agent subclass. Call the factory inside the original benchmark's `model_adapter`, after its request instrumentation is installed, then explicitly select the returned class in a new experimental bundle. The factory does not assign to original module globals/classes. Existing commands execute freshly compiled, hash-checked original command/choose bodies with private globals; existing click/fill/select/scroll guards remain the original code.

The model receives one additional targetless operation criterion, `FIND_TEXT`, and no extra response head. Its actual probability argmax must select that operation. The existing text helper generates a literal query using the unchanged `TEXT_VALUE` schema; the `field` is labelled `browser_find_query`, a logical navigation parameter, rather than an observed input. Current goal, observed page text and recent history supply the context. There are no benchmark routes, task patterns, selectors, gold answers or judge inputs in the component.

Every find attempt consumes one of the existing sixteen actions, including stale, helper error, timeout and no-match attempts. Decisions are consumed before helper/navigation so a replay cannot repeat navigation. Typed feedback is retained per agent for the last four attempts and included in the next model request. Queries, request bodies and feedback remain equal in sent/returned request objects; no task success is inferred. Ordinary existing operations still use the original implementation.

The new navigation function requests a single owned-session CDP evaluation. JSON data carries the query; it is never interpolated as code. It checks the original page marker before scanning and immediately before scrolling. The bounded scan searches literal, case-sensitive text within individual rendered text nodes of the current document body, excluding hidden/script/style/template content. It supports offscreen rendered content; it does not cover cross-node phrases, frames or shadow trees. It scans at most 50,000 nodes/200 ms and uses at most a 500 ms CDP evaluation timeout inside a cooperative twenty-second action timer. A blocking transport cannot be hard-cancelled or undone; late returned navigation evidence is retained with a `late` flag. `scroll_requested` records a request, `scroll_changed` records immediate top-level scroll coordinates, and neither means a click, typed input, task success or independently verified visual delivery.

`private_protocol.load_private_protocol()` provides separately named, hash-checked generated-action, legal-grammar and Decision3 native adapter modules. Exact inverse byte comparisons permit only the new operation whitelist/count and explicit profile identifiers/import seams. All model/numerical functions, ordered payloads, native255 cap, singleton evaluation, native argmax and existing grammar token/action limits remain unchanged. Over-limit requests are rejected without pruning. The current browser has one operation head plus up to three target heads; historical fifteen-head totals are sums across requests, not a fixed browser geometry.

The original server continues to reject `FIND_TEXT`. A new explicitly selected server/API import, native wire-profile selection, source/bootstrap descriptor and benchmark constructor binding are still required before a real run. The component does not load a model, launch a service, modify a qualified source population or claim that the current owner accepts it. Q95 text-schema compatibility does not qualify a policy endpoint or establish query quality.

Validation: **26 CPU tests passed in 2.34 seconds on the final reviewed source** using actual selected original Python bodies and fake I/O. They cover original module isolation, full question/candidate ordering, native255 and singleton handling, actual native argmax rejection, grammar limits, exact helper schema, sixteen-action/thirty-two-prediction limits, stale-before/after-helper and final navigation gates, late output evidence, per-agent feedback and ordinary operation delegation. A tiny CPU Node fixture executes the actual generated JavaScript against a fake DOM for long-page matches, literal quote/backslash data, no-match, hidden text, scan limits and final staleness. No real browser/CDP, model/GPU, helper HTTP, unit, Comfy or task judge was run. Real browser behavior and task quality remain unverified.

See `research-decision.md`, `source-pins.json`, `source-parity.json`, `validation.json` and `cpu-tests.xml` for the exact source and validation scope.

No real browser, helper, model, unit or Comfy operation was performed.
