# Invented browser-domain Decision3 canary candidate

This source-only candidate distinguishes browser-question understanding and
option-position sensitivity without official tasks, gold, saved observations,
or a trained/calibrated replacement model. It has not run a neural network.

The six cells are fixed before execution: red lantern with a usable switch,
green lantern with its goal already achieved, and static red lantern without a
progress-making control; each uses original and reversed criteria order. All
three observations retain the original snapshot's unconditional WAIT control;
the unavailable room explicitly will not update. The paired tiny DOMs
and observation DTOs were independently authored. Observations are synthetic,
not extracted by Chromium. Their expected CLICK/target1, DONE, BLOCKED predicates
are diagnostic labels and never enter the model input. There are no adaptive
controls or additional model requests. A wrong legal decision is retained and
reported; it cannot trigger a fallback, helper call, physical action, or retry.

The pinned original browser `action_space`, `validate_choice`, and `choose`
function ASTs run unchanged in an isolated namespace. The two original literal
question instructions are unchanged. Only their transport callback is explicitly
in-process; no upstream HTTP module/client is imported and no HTTP qualification
is asserted. Reversal changes the actual submitted criteria before DTO
validation and request-bound wire conversion. Original constructed input and
actually submitted input are retained separately in local raw evidence.

The original GPU adapter constructor rejects CPU. This candidate does not alter
or bypass it. It has a distinct truthful CPU-only constructor which checks the
original owner06 resources and frozen native02 runtime, then runs the exact
original `JevDecision3NativeAdapter.predict` AST with a new diagnostic profile.
The original DTO, payload preparation and response normalizer are imported from
their pinned sources. Wire conversion function ASTs are unchanged; only their
isolated profile constants name this diagnostic. No fake CUDA spec is supplied.

Actual NN loading, one constructor, original BF16 backbone/FP32 255-code head,
temperature1, CPU reference kernels and backend come from frozen native02.
Its maximum native batch is4. Actual original requests have2,2,1 heads (twice
each); no dummy questions or extra rows are inserted. A returning-None pre-hook
observes actual row count/CPU/BF16/width, without reading or changing values.
The full browser prompt must fit8192 tokens; nothing is truncated. This is a
new CPU diagnostic, not a reproduction of the historical GPU batch8 campaign.

Owner06 remains CPU16–19/400%, fixed2GiB, swap0, original runtime reserve
26,119,172,916B and startup reserve plus full cap28,266,656,564B, runtime10800.
Fresh original admission and later authenticated external closure are required;
source qualification does not supply either. No original authority is modified.

Each20s request includes original building, DTO/mapping, NN, raw evidence,
validation, hook removal, durable state write and watchdog cleanup. Whole120s
starts at `execute()` entry, includes preflight/loading/final full model and
source authentication/final write/watchdog cleanup, and has a literal elapsed
check before successful return. Main CLI printing and external owner/root wall
are separate; root must inspect their saved elapsed/exit/closure. Any late,
cleanup or evidence failure demotes completion; secondary failures preserve the
original exception. A successful diagnostic may have zero semantic matches.

Future raw toy requests/responses stay in the fresh output, whose own .gitignore
is written before model loading; this source directory also ignores actual-*
and raw-toy files.
The state contains only decisions, counts, shapes, timing and resource evidence.
All JevBench/browser scores remain null; model/HTTP/no-escape qualification
flags remain false. This does not replace1479 benchmark calls or10 real browser
tasks and does not establish readout training feasibility or browser usability.

Source tests are bounded stdlib fakes only and must run after any real model
workload is terminal, on CPU0 with address-space256–512MiB and CPU30s. They can
exercise extracted browser functions against synthetic distributions but never
import Torch, pydantic/native DTO modules, model packages, or start an owner.
Source/runtime qualification still requires an independent frozen review and
an exact root selection before any future actual execution.
