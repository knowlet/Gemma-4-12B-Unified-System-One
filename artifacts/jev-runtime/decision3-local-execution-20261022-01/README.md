# Selected local Decision3 execution

This isolated composition connects the frozen current-source bootstrap to the
frozen local worker transport and the unchanged V7 browser benchmark. It is a
prepared execution path, with no actual Decision3 or browser score yet.

`launch_execution.py` defaults to a source-only report. Importing these files
starts no process, listener, framework, unit or model. Actual execution is an
explicit operation:

```text
<selected interpreter> -B -s launch_execution.py --execute --role controller \
  --plan <sealed-plan.json> --plan-sha256 <independently selected SHA256>
```

The controller takes the exact bytes and independently selected hash of the
plan. It authenticates its own entry and execution source before importing the
implementation. Selected private/project modules compile authenticated source
bytes, so a valid timestamp/size bytecode cache cannot replace selected code.
Installed runtime versions, source/METADATA pins and origins remain the frozen
bootstrap's observation scope; this is not an attestation of every interpreter,
library, compiler, kernel or DSO byte.

## Selecting a plan

`execution.prepare_plan(...)` prepares a dictionary for review. It starts
nothing and does not authorize its own result. Save its canonical bytes and
select their SHA independently before using `--execute`. Required inputs are
the selected model, fresh host boot/MemTotal/GPU UUID, a launch expiry on the
same boot, distinct unit names/nonces, distinct fresh model outputs, the reviewed
helper checker source, two helper selections/bindings, and the browser selection.

Choose the two unit names first and supply them as `units={known4: ..., public6:
...}`. Each helper descriptor's `co_resident.cgroup` must name its corresponding
unit. Both descriptors bind the same fresh Q95 helper and selected D3 model.
Supply `nonces` to bind an independently prepared owner selection. The checker
must be `decision3-local-helper-binding-20261022-01/live_helper.py`, separately
reviewed and selected by its complete source reference. A Q93 helper or a
current-source fallback cannot be relabelled Q95.

The browser selection has exactly `interpreter`, `upstream_path`,
`upstream_commit`, and `chromium={path,sha256,size_bytes}`. The interpreter must
match the selected bootstrap runtime. The controller checks the upstream commit
and clean tracked worktree and streams the selected Chromium hash. The plan's
`sources` population contains the selected nineteen-source bootstrap union,
integration files, original browser/profile files and helper descriptors, with
at most 64 references. Nested bootstrap/helper runtime references keep their
own independent source authority; model payloads are never outer source refs.

The overall evidence output must be a fresh ordinary directory inside this
integration directory. Actual model outputs must be separate fresh directories
inside the original `artifacts/jev-d3-native` boundary. The worker creates a
fresh per-nonce publisher module cache and establishes the original offline
environment before calling the frozen bootstrap. No interrupted output is
overwritten or reused.

## Actual sequence and unchanged behavior

The controller creates known4 and then public6 as separate selected units.
Each actor publishes its actual PID/start/session/cgroup. Before constructing a
model, the external owner reads actual systemd and kernel properties, records
the Invocation ID, and publishes a plan/nonce/readback-hash-bound admission.
The actor and model child recheck actual identity, parent and cgroup membership.

The explicitly selected D3 owner profile is 80 GiB, swap zero, runtime 7200 s,
control-group termination and no delegation. Only this new D3 profile changes
the frozen owner's 40 GiB admission ceiling. All other owner validation,
Invocation/cgroup/readback/stop/closure behavior is reused. Gemma's separate
40 GiB policy is untouched. The original CORE reserve and
`min(host available, cgroup headroom) >= R + 2D + 2 GiB` remain unchanged. A
model that cannot satisfy the actual floor refuses before the framework or
constructor, as in the frozen bootstrap.

Each model worker runs real `bootstrap_selected`, its original publisher text48
warmup and unchanged native request helper. All six models remain selectable.
Native 255-element capacity, batch8, BF16 backbone, FP32 readout, temperature1,
context8192, no permutation averaging and no fast path stay in the frozen
implementation. This composition does not crop observations or change model
response conversion.

The model child is offline. It asks the parent actor for fresh helper admission
through authenticated control frames bound to PID/start/nonce/model/GPU/boot,
request phase, sequence and frame hash. Parent admission checks the actual
owner, fresh known idle/absent Comfy observation, selected sources, and the real
helper checker. Helper credentials stay in parent memory and the browser's
separate text environment. They are never sent to the model child or included
in the plan, argv or control receipts. Policy and text credentials differ.

The external controller continuously observes the pinned Comfy queue/absence
probe and host every two seconds while a unit starts or runs. Busy/unknown
Comfy state, host identity drift, or available memory below the existing native
owner margin `R + 2 GiB` immediately enters authenticated stop of the selected
own unit. The actor checks the same guard while the browser runs and at each
helper callback. The original full Q95 and D3 admission floors still apply at
their live/bootstrap/request gates. No guard stops or modifies Comfy or another
unit. A separately launched Q95 helper requires its own guarded owner.

Before and after each native request, the child requires a fresh helper
callback within the same original request budget. The real frozen loopback
gateway retains its 20 s deadline and prepared-header publication gate. A late,
refused or mismatched candidate produces no browser action. Finalization
reauthenticates geometry, raw Driver/Torch/host identity, complete model cache,
selected source/runtime and offline evidence, and closes the backend with a
CUDA fence. The original initial-cache receipt is compared to full final cache
authentication; `Components.close()` alone is insufficient.

The exact original groups are:

Each uses the unchanged V7 bundle, one repeat, 16 steps, seed20261014 and original
judges. Success requires fresh verification, a `done` final state and no error.
The final result keeps all ten tasks in its denominator, including missing or
infrastructure failures. Each group must close its selected external unit and
observed cohort before the next can start. The frozen transport's honest
`whole_tree_exit_confirmed=false` is retained; the external owner separately
proves scoped selected-unit closure. Universal no-escape/security claims are
neither required nor made.

## CPU verification

`test_execution.py` runs owned tiny subprocesses and actual loopback HTTP through
the real transport, selected bootstrap authority and original request helper.
Its fixture profile explicitly uses a tiny adapter, no framework/model, no
publisher warmup and no model qualification. Tests cover exact original payload
bytes and all 255 elements, helper control binding/refusal/deadline, pre-constructor
authority/expiry/owner rejection, actual direct-child cleanup, scoped owner
readback rules, original workloads/judges, and stale-bytecode resistance.

No actual model, GPU, browser, unit, helper or Comfy operation is part of this
CPU verification. Actual Q95 launch feasibility, fresh coexistence/resource
admission, actual model startup/kernel/geometry evidence and the full ten-case
result remain future execution evidence, not facts established by these tests.
