# Context-first GPU measurement decision

Previous goal turn is **progress**: commit145ff221bac1dc54ac75ceded2f668aa46999870 completed actual checkpoint decoder0/5 CPU measurement with all four cases/eight forwards and independent saved-result/owner audits. It did not qualify GPU or full-model usability. This continuation first measures CUDA context and a tiny operator under a separate profile; it does not construct a model or read checkpoint bytes.

Research before implementation used installed Torch2.13.0+cu130 sources and primary documentation:

- NVIDIA [Unified and System Memory](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/understanding-memory.html): a common virtual address space alone does not establish GPU access to arbitrary file mappings. Managed/system access and coherency depend on actual device attributes and platform support. This probe adds no host registration, mapped tensor alias, managed allocation or direct file access.
- NVIDIA [CUDA for Tegra](https://docs.nvidia.com/cuda/cuda-for-tegra-appnote/index.html): shared-DRAM platforms require care interpreting device and host memory. Its platform-specific features are not assumed to apply to GB10 without measurement. Host MemAvailable and CUDA free must not be added as independent memory pools.
- [PyTorch CUDA semantics](https://docs.pytorch.org/docs/stable/notes/cuda.html) and [mem_get_info](https://docs.pytorch.org/docs/stable/generated/torch.cuda.memory.mem_get_info.html) redirect to2.14 at research time. Explicit2.13 URLs were inaccessible. Installed2.13 source is therefore the API authority for this run, not newer documentation.

Installed `torch/cuda/__init__.py` shows explicit `init()` invokes lazy initialization; `get_device_properties()` does so too. `torch/cuda/memory.py` shows `mem_get_info()` calls the CUDA runtime, `set_per_process_memory_fraction()` initializes CUDA and limits only the own caching allocator, and `empty_cache()` releases own unoccupied cached memory. CUDA free cannot be measured through these APIs before initialization without altering the baseline. Pre-init GPU allocator/free values are therefore **unmeasured**, while own-process/cgroup/host snapshots are available. Subsequent snapshots distinguish those scopes and include synchronized tiny work.
