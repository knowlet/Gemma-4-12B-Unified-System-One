# Held frozen-candidate dev feature collector

This is an unselected source-only port of the already pushed train collector.
No prior file was changed. `eval_collector_held.py` has `SOURCE_ONLY=True` and
pending dev-capability/numeric-acceptance pins. It refuses before parsing CLI
arguments, plan reads, imports, outputs or model work. Changing that flag alone
still refuses pending pins. No import, AST, test, formatting, hash, builder,
actual, split-data, label, capability-data or host operation was executed during
this authoring pass. No runnable plan, launcher, score or result is supplied.

The only role is `dev_feature_collector`, fixed split `dev`. There is no CLI
split/reveal switch. Every ordinary read, including generic prerequisite refs,
rejects all files under the DSL package except the exact dev `requests.jsonl`
and `summary.json` exports. Labels, train, sealed, authoring source, full manifest
and authored cases are refused before open. No DSL Python module is imported.
This is a path/role contract, not an OS access-sealing claim.

The dev population is fixed at24 original snapshots from one family and three
ancestors, eight snapshots per ancestor. The authoring pass did not inspect
their requests, labels, summary or family/ancestor identities. Those exact
identities must come from a separately pinned root dev export capability;
they are not guessed or regenerated here. The pure selector checks the complete
24-case inventory and selects all eight existing cases of one chosen ancestor
in original order. Duplicate, missing, altered or foreign-lineage requests fail.

The original `{state,questions}` projection and its digest are preserved; the
upstream `jev-latest` tag stays source metadata. Native05 binds actual inference
to its original d3-edge model. Every request still offers all four original
heads with counts8/4/4/4, while target-head and criteria insertion order stay as
authored. Feature rows map by actual head ID and ordered criteria, not by a
constant target-head list. No helper answers, labels, option repairs, dummy rows,
extra encoder passes or input truncation are introduced.

Before collection the future plan must pin the exact previously frozen train
candidate and its genuine trained-readout root acceptance. It must also pin the
closed numeric composition root acceptance and original terminal/owner/current
closure references. The candidate capability must bind the unchanged model and
state that it was frozen before dev/sealed/browser/benchmark exposure; its delta
reference must agree with the numeric root acceptance. These are trusted exact
root acceptances, not independent producer re-audits by this child. The source
does not load the trained delta or any train feature/label arrays.

The dedicated dev export capability additionally binds dev input hashes, frozen
candidate, numeric acceptance, one family/three ancestors and the selected
ancestor. It explicitly disallows labels, training eligibility and sealed reveal.
Root must select that capability under the existing corpus role policy without
importing reconstructive authoring code into this child. Source pins and metadata
must be checked before any future release; none is manufactured by this port.

Each invocation reuses the original owner09/native05/NP02 source composition:
CPU15–19, quota500%, five intra-op/one inter-op threads, full4GiB, swap0,
reserve26,119,172,916B, startup30,414,140,212B. One genuine CPU BF16 model
constructor serves the complete eight-case ancestor chunk. Each request has one
real four-row forward. The original first-layer/final-norm hooks return `None`
and retain only detached last-position FP32 h. The original FP32255×1024 W0,
temperature1, preparation, masks, context16384 and kernels stay unchanged.

The existing same-forward Torch and zero-delta NumPy checks, complete legal
distribution/argmax/entropy validation, baseline-identity checks, full model and
source authentication, catalog bounds and readonly array copies are retained.
No trained candidate backend runs here. Later readout evaluation can compare
zero/candidate on these same features after separate closed collection acceptance.

NP02's complete call20 includes first-call catalog authentication and numerical
imports, native request, copies/replays, raw/array/evidence retention, full native
authentication, hook cleanup, directory sync and watchdog exit plus the literal
final time check. Whole120 includes preflight, cold model construction, eight
calls, final input/source/model authentication, manifest/state writes and cleanup.
The original parent owner still owns admission, service observation and closure.
Failure stays incomplete and may leave diagnostic files; no partial chunk is
accepted or scored. Source tests cannot establish8-call latency or memory fit.

All case/raw/h/W0/manifest outputs are private local `PENDING_DEV_NONTRAINING`,
carry split/role taint, labelsNone and `training_eligible=false`, including after
numeric success. There is no train `COMMITTED` authority, optimizer, fit, loss,
gradient, calibration, metric calculation, semantic score or browser pass.
The original train collector and train-only loader remain unchanged.

A complete dev collection needs three independently selected original-owner
chunks under the same frozen candidate/model/source identities, covering all24
cases exactly once. The later evaluator must first accept original terminal0,
owner completion/current authenticated closure and source/payload hashes for
every chunk, then read only dev labels in its separate role. It must score all
legally supervised soft-target heads, skip unused heads, retain complete valid
sets and use stable log-probability CE. That evaluator is not implemented here.
Sealed48 stays unrevealed and has no entry in this source. Opening it requires
a separate final-candidate reveal selection; no current Boolean authorizes it.

`test_eval_collector_held.py` contains only unexecuted stdlib fakes with an
