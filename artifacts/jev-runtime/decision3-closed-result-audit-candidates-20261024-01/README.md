# Held closed-result audits for full06 actual04

These two read-only review candidates are bound to the existing selected
owner07/native03/full06 actual04 run. They are source preparations, not results.
Root and a separate source reviewer read them against the frozen producers.
Neither candidate has been imported, AST-checked, formatted, dry-run, tested or
executed. Small source hashing and Git publication do not qualify execution.
All such checks remain held until the original NN and controller are terminal.

Both CLIs default to descriptive metadata without reading actual evidence.
An explicit `--execute` first requires the original root terminal and owner
receipt. No model, scorer, browser or service is started; the later audit reads
closed evidence, hashes selected original files and writes a new exclusive
aggregate review. Current source review does not authorize skipping the held
checks or the original current closure requirements.

`complete_audit_v02.py` accepts only original successful root/owner execution,
all1479 native callbacks, final full authentication, both authenticated stage
receipts and the original scoped closure. It joins the sealed config, exact
54+5 source union, admission/bootstrap/command identity, original clock scopes,
model20/runtime28 and scorer78 plus2 metadata identities, accepted smoke refs
and typed global official metrics. The earlier private complete-audit v01 has
known source gaps and is not included or selected.

`public_stage_audit.py` implements the predeclared full04/full05 rule for an
authenticated complete public231 stage surviving a later coherence failure.
It requires the original current closure itself to pass and a positive first
coherence callback to prove the public completion's final handoff returned.
It keeps the nonzero root exit, owner failure, original primary/secondary
errors, overall incompleteness and absent coherence qualification. Later
absence scans never repair false original closure flags. A marker alone is
not sufficient. This actual04 audit deliberately requires a validated first
coherence callback as a conservative sufficient witness; it can refuse a public
stage whose first later callback entered and then timed out. It is not a general
entry-only fallback. The original retry04 terminal profile and full controller
arguments are bound, UTC timestamps require an explicit timezone, and public
publication/continuation durations must fit the original root wall time.

Both candidates preserve the original four-times-positive-period CPU quota
rule, rather than adding a fixed kernel period. They keep the original
campaign10000/owner10800 timing scopes. Official accuracy uses n_scorable;
structured ECE and coherence globals retain the original typed allowlists.
Memory pressure/peak readings, Report.errors and stderr are diagnostics,
not new zero-pressure, zero-error or empty-stderr score thresholds.

No raw tasks, gold, responses, tensors, error text, command stdout/stderr or
model bytes are copied into a public aggregate. Original records remain local
and are joined by references and hashes. There is no new score, fit, timing,
training, browser, rank or competitor-win qualification in this directory.
After the active run terminates, finish appropriate source checks, re-pin any
changed audit source, select the applicable path and independently review its
actual output before reporting results.
