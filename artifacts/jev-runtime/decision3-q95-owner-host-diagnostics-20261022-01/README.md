# Bounded Q95 host-refusal diagnostics

This source-only successor preserves the original host admission checks and all owner lifecycle and cleanup bodies. A rejected host row now attaches the gate, initial/runtime phase, exact reserve threshold, and typed scalar facts for boot ID, MemTotal, MemAvailable, Comfy state and running/pending counts to the original ValueError. Existing error_record() retains that evidence in owner receipts.

The same sanitized JSON is emitted once to stderr before re-raise, including the startup check that precedes output-directory creation. Each emission is at most 4096 bytes; logging failure does not replace the original refusal. No arbitrary observer evidence, queue objects, prompts, requests, credentials or exception text are copied. Unknown complex values are represented by type only; strings and malformed integers are bounded.

The source has an explicit preparation-only profile. There is no launch entrypoint or selected plan. The inherited04 unit/service constants are historical dead slots, and this component does not authorize reusing them. A future fresh owner must explicitly select new slots and seal its own source/plan.

Validation uses only fake observers and checked original source bytes: eleven tests include 58 original-versus-successor admission/error comparisons, exact threshold boundaries, secret exclusion, bounded malformed values, diagnostic I/O failure, observer-error identity, and unchanged cleanup/host predicates. Safe Ruff ran with one CPU and no address-space limit. No actual host observer, HTTP request, model, framework, browser, actor, unit or foreign process operation was invoked.

The exact historical helper04 failing host stage remains unproven; this improves future evidence rather than assigning a cause to that run.
