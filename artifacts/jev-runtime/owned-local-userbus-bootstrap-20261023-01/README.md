# Same-Python local user-bus bootstrap

This dry-default source candidate fixes the transport setup for the original read-only `systemctl --user show` query. The frozen controller intentionally starts children with a clean environment. It omits XDG_RUNTIME_DIR and DBUS_SESSION_BUS_ADDRESS; the catalog's first admission query therefore failed before catalog output, native-file hashing or runtime import. The closed actual04 remains a failed attempt and is never resumed.

`bootstrap.py` derives `/run/user/<euid>` and its `bus` socket from the current ordinary user's numeric identity. It requires the real/effective user and group credentials to match, a canonical same-user directory with mode0700, and a same-user Unix socket with an explicitly accepted mode0600,0660 or0666. The private0700 parent isolates the socket even when its mode is0666. It never uses an inherited bus address and never opens a network or bus connection. It adds only XDG_RUNTIME_DIR and `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/<euid>/bus`; it does not copy session environments, set HOME, fetch credentials or alter service state.

Execution requires one of two exact selected interpreters (ML logical Python3.13 for catalog; system /usr/bin/python3.12 for the helper parent), its matching canonical path and four-field stat identity, the original `-B -s` flags, no preloaded model modules, the wrapper's own SHA256 and the entry's SHA256. The entry must be an absolute canonical small ordinary Python source in this repository's runtime source tree, owned by the current user, without symlinks, hardlinks, special permission bits or writable group/other permissions. The wrapper verifies source bytes before dispatch and after entry completion. It rechecks local bus identity and the two selected environment values after completion as well.

The original entry runs through stdlib `runpy.run_path(..., run_name="__main__")` in the same Python PID and executable. Its `__file__` and `sys.argv` identify the original entry and arguments; the OS command line remains the exact root-selected wrapper command. This avoids an intermediate `/usr/bin/env` process/executable handoff. The source uses explicit file loaders, so its original owner/process/argv joins remain based on the same actual observed process. The wrapper neither monkeypatches boundary/status code nor grants new owner authority.

A successful entry `SystemExit(0)` remains subject to final authentication. If that authentication fails, the wrapper exits with failure. A nonzero exit or other original exception remains primary if final authentication also fails, with a diagnostic note for the secondary failure. No model, browser, latency or no-escape qualification is emitted by the wrapper.

The root command has this form, with all hashes and fresh output selected explicitly:

```text
SELECTED_PYTHON -B -s bootstrap.py --run --expected-wrapper-sha256 WRAPPER_SHA --entry ABSOLUTE_ORIGINAL_ENTRY --entry-sha256 ENTRY_SHA -- ORIGINAL_ENTRY_ARGUMENTS
```

`entry-requirements.json` pins the unchanged catalog02 entry/plan and helper03 parent entry/plan, with a separate exact interpreter prefix for each. The selected ML logical interpreter is allowed to be a symlink; the ordinary-source symlink refusal does not apply to interpreter selection. The helper parent retains its own pidfd feature requirement and separately spawns its unchanged ML worker. It supplies no completed catalog references or actual output. The default command without `--run` is metadata-only and performs no entry or bus operation. The old controller, observer, boundary, catalog and helper source files are unchanged. CPU4, cap2GiB, swap0, reserve R, the initial full R+cap floor and all original admission/process/resource/authentication checks remain required in their original sources.

The original catalog600, helper-parent180 and per-request20-second timer scopes remain unchanged. Wrapper preflight and final reauthentication are additional startup/teardown work outside the original entry timer. Any complete-command600/180-second claim must also check the exact saved root command wall time against that same fixed budget; the wrapper supplies no additional qualification window. Cold startup and per-request timing remain separate. The outer owner7200 ceiling remains an independent guard.

Fifteen bounded stdlib tests passed using fake bus metadata and tiny owned source fixtures. One real stdlib runpy fixture verifies PID, executable, `__file__`, arguments and exactly the two computed environment changes; no original entry, real bus, ML, service, observer or HTTP request was executed by these tests. Root's separate saved read-only contrast reproduced clean-env failure and verified that only the two local bus values allow the unchanged query to return the already closed unit as not-found. That contrast does not qualify a new actual run.

Independent peer review, a new exact root command selection, fresh original admission and fresh output are required before any future catalog/helper execution. Original authenticated closure and source preservation remain required afterward. No-escape and whole-tree enforcement remain false.
